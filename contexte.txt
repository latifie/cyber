## STRUCTURE DES DONNÉES SOURCES

### Répertoire racine
/ssd/cyber/

### Fichiers JSONL (années) - Stats générales
Emplacements:
  - 2022/, 2023/, 2024/, 2025/ : fichiers .jsonl par mois (01.jsonl, 02.jsonl, ...)
  - __2023/, __2024/ : fichiers compressés .jsonl.zst

Format JSONL (une ligne = un domaine):
```json
{
  "rd": "domaine.com",
  "fqdn": "domaine.com",
  "url": "https://domaine.com/path",
  "sid": "source_id",
  "discovery_time": "2024-01-15T10:30:00" ou timestamp,
  "metadata": {
    "discovery_time": "2024-01-15T10:30:00",
    "src": "source_name",
    "trg": "target_name"
  },
  "whois_bd": {
    "cd": "2023-12-01",  // Date de création du domaine
    ...
  },
  "takedown": {
    "uptime_dur": 720,  // Durée en heures
    "takedown_reason": "content"|"dns"|"whois",
    ...
  },
  "uptime": [  // Optionnel - rare dans JSONL
    {
      "dt": "2024-01-15T10:30:00",
      "type": "dns",
      "dns_status": "NOERROR"|"NXDOMAIN",
      "arec": [...]
    },
    ...
  ]
}
```

### Fichiers Uptimes - Transitions DNS temporelles
Emplacement: uptimes/*.json.zst ou uptimes/*.json

Format JSONL (une ligne = un domaine avec historique complet):
```json
{
  "rd": "domaine.com",
  "fqdn": "domaine.com",
  "url": "https://domaine.com/path",
  "sid": "source_id",
  "discovery_time": "2024-01-15T10:30:00",
  "metadata": {...},
  "whois_bd": {
    "cd": "2023-12-01",
    ...
  },
  "takedown": {...},
  "uptime": [  // Array d'entrées temporelles ordonnées
    {
      "dt": "2024-01-15T10:30:00",
      "type": "dns",
      "dns_status": "NOERROR",
      "arec": ["1.2.3.4"]
    },
    {
      "dt": "2024-01-20T14:00:00",
      "type": "dns",
      "dns_status": "NXDOMAIN"
    },
    {
      "dt": "2024-01-25T09:00:00",
      "type": "whois",
      "whois_status": "active"|"inactive"
    },
    ...
  ]
}
```

## OUTPUTS GÉNÉRÉS

### Répertoire de sortie
analysis_results/

### Fichiers de données générés

#### down_domains.jsonl
Liste complète des domaines avec transition NOERROR → NXDOMAIN détectée.

Format (une ligne JSON par domaine):
```json
{
  "rd": "domaine.com",
  "fqdn": "domaine.com",
  "url": "https://domaine.com/path",
  "sid": "source_id",
  "discovery_time": "2024-01-15T10:30:00",
  "dt": "2024-01-15T10:30:00",
  "metadata": {...},
  "transition": {
    "transition_date": "2024-01-20T14:00:00",  // Date transition NOERROR→NXDOMAIN
    "previous_date": "2024-01-15T10:30:00",
    "previous_status": "NOERROR",
    "new_status": "NXDOMAIN",
    "remains_nxdomain": true,  // true = illégitime, false = légitime (re-up)
    "year": "2024"
  },
  "whois_bd": {
    "cd": "2023-12-01",  // Date création
    ...
  },
  "takedown": {
    "uptime_dur": 720,
    "takedown_reason": "content"|"dns"|"whois",
    ...
  },
  "dns_context": {
    "before": [  // 5-10 entrées DNS avant transition
      {"dt": "...", "status": "NOERROR", "arec": [...]},
      ...
    ],
    "transition_index": 5,
    "after": [  // 10-20 entrées DNS après transition
      {"dt": "...", "status": "NXDOMAIN", "arec": []},
      ...
    ]
  }
}
```

## FONCTIONNALITÉS DU SCRIPT

### 1. Traitement des données (streaming)
- parse_jsonl_stream(): Lit fichiers JSONL ligne par ligne (support .zst via zstdcat)
- parse_uptime_stream(): Lit fichiers uptimes (même format JSONL)
- process_domain_record(): Traite enregistrements JSONL (stats générales)
- process_uptime_record(): Traite enregistrements uptimes (transitions DNS temporelles)

### 2. Détection transitions DNS
- Détecte transitions NOERROR → NXDOMAIN dans historique uptime
- Vérifie si transition permanente (reste NXDOMAIN) ou temporaire (re-up)
- Export dans down_domains.jsonl avec contexte DNS

### 3. Calculs de délais
- Création → Utilisation: Délai entre whois_bd.cd et discovery_time
- Achat → Takedown: Délai entre whois_bd.cd et transition.transition_date
- Filtrage valeurs aberrantes (< 0 ou > 50 ans)

### 4. Analyses temporelles
- Groupement par année (extraction depuis dates)
- Groupement par période 6 mois (YYYY-H1/H2)
- Comparaisons inter-années

### 5. Génération visualisations
- Tous graphiques en 300 DPI, format PNG
- Utilisation matplotlib avec backend Agg (non-interactif)
- Libération mémoire après chaque graphique (gc.collect())

## UTILISATION

### Mode normal
```bash
python3 analyze_domains.py
```
Traite tous les fichiers disponibles, génère tous les graphiques et rapports.

### Mode test (limite lignes)
```bash
python3 analyze_domains.py --test [--test-limit N]
```
- --test: Active mode test (limite par défaut: 200 lignes/fichier)
- --test-limit N: Spécifie limite personnalisée

### Mode DNS-only
```bash
python3 analyze_domains.py --dns-only
```
Ignore fichiers JSONL (années), traite seulement fichiers uptimes/ pour transitions DNS.

## NOTES IMPORTANTES POUR L'IA

### Structure des données
- JSONL = une ligne JSON par enregistrement (pas de tableau global)
- Fichiers compressés .zst lus via zstdcat en streaming
- Dates: formats variés ('%Y-%m-%d', '%Y-%m-%dT%H:%M:%S', timestamps)

### Filtrage domaines illégitimes
- remains_nxdomain = true → Takedown illégitime (reste NXDOMAIN)
- remains_nxdomain = false → Takedown légitime (re-up, redevient NOERROR)

### Périodes 6 mois
- Format: "YYYY-H1" (jan-juin) ou "YYYY-H2" (juil-déc)
- Basé sur date de transition (takedown), pas date création

### Optimisations mémoire
- Toujours streaming ligne par ligne
- Pas de chargement complet fichiers en mémoire
- Libération mémoire périodique (gc.collect())
- Stats agrégées seulement, pas données brutes

### Dépendances
- Requis: python3, zstd (pour zstdcat)
- Optionnel: tqdm (barres progression), matplotlib/pandas/numpy (graphiques)
